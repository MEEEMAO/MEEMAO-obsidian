Mem0 and Cognee through Agent Memory Taxonomy

這份講義用 Memory in the Age of AI Agents 的三個角度，也就是 Forms、Functions、Dynamics， 來拆解 Mem0 與 Cognee 的 memory structure。重點不是介紹工具功能，而是回答： 它們到底把記憶存成什麼、服務什麼能力、又如何被建立、更新與取回。

1. 先用同一套框架看 memory

Memory in the Age of AI Agents 不只把 memory 看成「短期或長期」，而是拆成三個分析軸：

Forms: memory lives where? 看記憶的載體。是 token-level 的外部資料、parametric 的 model weights，還是 latent state / hidden representation。
Functions: memory is for what? 看記憶支援什麼功能。它保存事實、保存經驗，還是支撐當下任務的 working memory。
Dynamics: memory changes how? 看記憶如何形成、更新、遺忘與檢索。這是 agent memory 和單純 storage 最大的差別。

在這個框架下，Mem0 和 Cognee 都主要屬於 token-level external memory： 它們不是把知識直接改進模型權重，而是在模型外部建立可查詢、可更新、可追蹤的 memory layer。

2. Mem0: long-term conversational memory layer

Mem0 比較像是為 AI assistant / agent 準備的長期對話記憶層。它的核心目標不是建立一個完整的知識圖譜世界， 而是從互動中抽出值得保存的 facts、preferences、events，讓 agent 未來能更快、更便宜、更準確地 recall。

Memory structure

conversation / interaction
→ LLM extraction or distillation
→ ADD-only memory facts
→ deduplication + embeddings
→ entity linking
→ retrieval by semantic + keyword + entity signals
Memory unit Mem0 的基本記憶單位比較像 distilled memory fact。它不是原封不動保存整段對話，而是把對話壓縮成可 recall 的事實或偏好。
Link structure Mem0 會做 entity linking，把不同 memory 裡的相同人、地點、物件、事件連起來。這比單純 vector search 更能處理「Alice 是誰」這類 entity-centric query。

Through Forms / Functions / Dynamics

Taxonomy angle Mem0 的位置 說明
Forms Token-level memory + vector/entity indexing 記憶存在外部 store。memory text、embedding、metadata、entity links 是主要載體。
Functions Factual memory 為主，部分 experiential memory 最適合保存 user preference、personal facts、conversation facts、cross-session updates。若把成功互動也抽成 memory，也可支援 experiential memory。
Dynamics: formation LLM extraction / distillation 系統判斷對話中哪些資訊值得變成 memory fact，而不是把所有 tokens 都放進 context。
Dynamics: evolution ADD-only temporal preservation + dedup context 新的 Mem0 架構傾向保留新舊 facts，避免直接覆蓋而丟掉時間脈絡。這和 A-MEM 的「改寫舊 note 表示」不完全一樣。
Dynamics: retrieval Multi-signal retrieval 同時使用 semantic search、keyword search、entity matching，再融合結果。這是它 production orientation 很強的地方。

用一句話說，Mem0 的 memory structure 是： 把對話壓縮成可長期保存的 memory facts，再用 vector + keyword + entity linking 做高效率 recall。

3. Cognee: graph-vector knowledge memory engine

Cognee 更像是把 raw data、documents、files、URLs 轉成 agent 可以查詢與推理的外部知識記憶系統。 如果 Mem0 偏向 conversational memory，Cognee 就更偏向 knowledge memory / structured document memory。

Memory structure

documents / text / files / URLs
→ ingestion + chunking
→ entity and relationship extraction
→ knowledge graph
→ embeddings
→ relational provenance
→ vector + graph hybrid retrieval
Memory unit Cognee 的記憶單位可以是 DataPoint、chunk、entity、relationship、summary。它更像是在把資料轉成一組可組合的 graph-vector objects。
Link structure Graph 是 Cognee 的核心之一。它不只是輔助 entity linking，而是讓 agent 能沿著 entities、relations、documents、provenance 進行結構化 traversal。

Through Forms / Functions / Dynamics

Taxonomy angle Cognee 的位置 說明
Forms Token-level memory + graph memory + vector memory 記憶存在外部 relational store、vector store、graph store。Graph 負責結構，vector 負責語意相似，relational store 負責 provenance。
Functions Factual memory / knowledge memory 為主 適合保存文件知識、研究 corpus、企業資料、程式碼知識、可引用來源。若加入 session memory，也能部分支援 working memory。
Dynamics: formation cognify / remember pipeline 資料被清理、切 chunk、抽 entity、抽 relation、建立 graph、建立 embeddings。formation 比 Mem0 更像 document-to-KG pipeline。
Dynamics: evolution improve / memify enrichment 可以對既有 graph 做 enrichment，例如 derived facts、edge weighting、session-to-permanent memory bridge。它的 evolution 偏 graph refinement。
Dynamics: retrieval Vector search + graph traversal + hybrid search 查詢時可以走語意相似，也可以走 graph relations，或兩者結合。這比單純 chunk RAG 更適合需要結構推理的問題。

用一句話說，Cognee 的 memory structure 是： 把外部資料轉成同時有 embeddings、graph relations、provenance 的 knowledge memory substrate。

4. 和 A-MEM 放在一起看

前面討論 A-MEM 時，我們把它理解成 weak schema + dynamic semantic organization。把三者放在一起，就能看出它們的 memory structure 重點其實不同。

Architecture 最像什麼 基本 memory unit Graph / link 的角色 Evolution 的重點
Mem0 長期對話記憶層 Extracted memory fact Entity linking and retrieval boost 保留時間脈絡、去重、提高 recall 效率
Cognee Graph-vector knowledge engine DataPoint / chunk / entity / relation 核心 knowledge graph substrate Graph enrichment、derived knowledge、usage-aware improvement
A-MEM Self-evolving note network Atomic memory note Zettelkasten-style semantic links 新記憶觸發舊記憶的 context / tags / keywords 更新

因此，如果問題是「KG 的 node 和 edge 不就已經很像 atomic memory 和 links 嗎？」答案是： 對，但差別在 graph 的語意是否固定、更新是否自動、以及 retrieval 是否只靠 graph。

5. 用一個情境比較

假設使用者長期和 agent 討論 AI memory 研究，並逐漸顯露出自己的研究偏好： 

User facts:
- 使用者在讀 agent memory survey
- 使用者關心 KG memory 和 A-MEM 的差異
- 使用者偏好先看 architecture-level intuition，再看 paper terminology
- 使用者可能想發展 AAAI research direction

Mem0 會怎麼存

Mem0 會比較像抽出個人化與對話延續需要的 facts： 

Memory fact 1: User is studying agent memory systems.
Memory fact 2: User is interested in KG-based memory and A-MEM.
Memory fact 3: User prefers architecture-level explanations before terminology.
Entity links: User ↔ A-MEM, User ↔ knowledge graph, User ↔ agent memory taxonomy

Cognee 會怎麼存

Cognee 會比較像把 papers、notes、concepts 變成可 traversal 的 knowledge graph： 

Document: Memory in the Age of AI Agents
Concept: Forms / Functions / Dynamics
Concept: Token-level memory
Concept: Knowledge graph memory
Paper: A-MEM
Relation: A-MEM → uses → Zettelkasten-style note network
Relation: Cognee → combines → vector store and graph store
Relation: Mem0 → uses → entity-linked long-term conversational memory

A-MEM 會怎麼存

A-MEM 會比較像把每段討論變成 atomic note，並持續改寫 note 的 context： 

Note:
content: User asks whether KG nodes and edges are already atomic memory and links.
tags: knowledge graph, memory schema, A-MEM, dynamic links
context: User is clarifying whether A-MEM's novelty is graph structure itself or dynamic semantic organization.
links: related to previous note about parametric vs latent memory; related to A-MEM note; related to agent memory taxonomy note.

6. 最精簡結論

Mem0 如果你的問題是「agent 如何長期記住使用者和互動歷史」，Mem0 是最直接的例子。 它的 memory structure 偏向 extracted facts + entity linking + multi-signal retrieval。
Cognee 如果你的問題是「agent 如何把大量資料變成可推理的外部知識結構」，Cognee 是更直接的例子。 它的 memory structure 偏向 graph-vector-provenance hybrid。
A-MEM 如果你的問題是「memory network 如何自動組織與演化」，A-MEM 是更直接的研究型例子。 它的 memory structure 偏向 atomic notes + dynamic links + memory evolution。 
Mem0: remember the user and conversations.
Cognee: organize documents and knowledge into graph-vector memory.
A-MEM: let memory notes self-organize and evolve.
