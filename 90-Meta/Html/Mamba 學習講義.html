0先看全貌：Mamba 想解決什麼問題？

一句話版本：Mamba 想要 Transformer 的效果，同時擁有 RNN 的速度。

語言模型（以及處理音訊、DNA、時間序列的模型）本質上都是序列模型：輸入是一長串依序排列的東西（文字切成的 token、聲音的取樣點、DNA 鹼基），模型要從「前面看過的內容」推斷「接下來是什麼」。

所以每個序列模型都要回答同一個問題：過去的內容要怎麼記？不同的答案，造就了不同的模型與不同的取捨。下面這張圖是整份講義的地圖，後面每一節都在拆解其中一部分。

我們希望一個序列模型同時做到三件事。下表是各家模型的成績單（看不懂沒關係，後面會一一解釋）：

模型訓練時能平行計算生成時每一步成本固定能依內容挑選資訊
RNN✗✓✗
LSTM / GRU✗✓△ 有閘門
Transformer✓✗ 越長越慢✓
舊式 SSM（S4 等）✓ 用捲積✓✗
Mamba✓ 用平行 scan✓✓

Mamba 的貢獻可以濃縮成三件事，也就是本講義的主線：

  1. 選擇機制（第 6 節）：讓 SSM 的參數隨輸入改變，模型才能「看內容」決定記住或忽略。
  2. 硬體感知演算法（第 7 節）：上面那個改動會讓原本的加速技巧失效，所以作者重新設計了在 GPU 上跑得快的算法。
  3. 簡化的架構（第 8 節）：把 SSM 和前饋層合成一種區塊，整個網路只重複堆這一種，完全不用 attention。

第 1 到 3 節先補齊需要的前備知識，第 4、5 節建立 SSM 的概念，之後才進入 Mamba 本身。

1前備知識：RNN 與 LSTM 怎麼「記住過去」

RNN 用一個不斷更新的「隱藏狀態」當作記憶。這是 SSM 和 Mamba 的直系祖先。

RNN（循環神經網路）一次讀一個 token。它手上隨時拿著一個向量 h（hidden state，隱藏狀態），可以想成「到目前為止讀到的內容摘要」。每讀到新的輸入 xt，就把舊摘要和新輸入混在一起，得到新摘要：

ht = tanh( W · ht−1 + U · xt )     yt = V · ht

這裡的 W、U、V 是要學的權重矩陣，而且每一步都用同一組。把時間軸攤開畫，就是下圖：

RNN 的優點是生成時很省：每來一個新 token，只要拿手上的 h 更新一次，成本固定，也不用回頭看舊資料。但它有兩個出名的缺點：

  • 訓練無法沿時間平行。要算 h100，得先算完前 99 步。GPU 擅長「同時做很多一樣的事」，這種排隊式計算很浪費它。
  • 梯度消失，記不了太遠。訓練時誤差要沿時間一路往回傳，每經過一步就被權重乘一次，傳到很早之前常常已經小到接近 0，模型就學不到遠距離的關聯。

LSTM 與 GRU：加上「閘門」

LSTM、GRU 是改良版 RNN，關鍵發明是閘門（gate）：一個介於 0 到 1 之間的數字，由當下輸入算出來，用來決定「舊記憶留多少、新資訊寫多少」。以簡化的 GRU 風格為例：

  • g ≈ 0：幾乎保留舊記憶，當下輸入被忽略。
  • g ≈ 1：舊記憶被清掉，換成當下輸入。

重點在於 g 是依當下輸入而定的，所以模型可以「看到重要的字就記，看到廢話就跳過」。請把這條公式記住，第 6 節會發現 Mamba 的選擇機制，在最簡單的情況下就退化成它。

本節帶走
  • RNN 用固定大小的狀態 h 當記憶，生成很省，但訓練得一步步排隊。
  • 閘門讓「記多少、忘多少」依輸入而變，這就是「選擇」概念的源頭。

2前備知識：Transformer 好在哪，貴在哪

Attention 讓每個 token 直接回頭看所有之前的 token。效果極好，但代價隨長度快速上升。

Attention（注意力）的做法是：每個 token 對之前每一個 token 算一個相關分數，再依分數做加權平均，把相關的資訊拉過來。比如讀到「他」的時候，可以直接去前文找「他」指的是誰。

這有兩個好處：第一，任何兩個位置之間都是「一步直達」，不會像 RNN 那樣傳遞時逐漸遺忘；第二，訓練時所有位置可以同時算（就是一個大矩陣乘法），很適合 GPU。

換個角度說：Attention 完全不壓縮記憶，它把整段歷史原封不動地留著，需要時再查。這就是它強的原因，也是它貴的原因。當序列長到數萬、數十萬（整本書、一小時的音訊、一條染色體），這個代價就很難承受。

補充：什麼是 O(L²)?

這是描述「成本怎麼隨輸入長度 L 成長」的寫法。O(L) 叫線性：長度變 2 倍，成本變 2 倍。O(L²) 叫平方：長度變 2 倍，成本變 4 倍；變 10 倍，成本變 100 倍。論文標題裡的 Linear-Time 就是說 Mamba 是 O(L)。

本節帶走
  • Attention 能精準取用任何歷史資訊，訓練可平行。
  • 代價是訓練 O(L²)、生成時 KV cache 隨長度一直變大。

3前備知識：捲積與 GPU 記憶體

兩個工具性的概念：捲積解釋了舊式 SSM 為何能快速訓練；GPU 記憶體階層解釋了 Mamba 的加速演算法。

一維捲積

你可能在影像的 CNN 裡看過捲積：一個小視窗（kernel，卷積核）在圖片上滑動。一維捲積是同一件事，只是在序列上滑：每個輸出，都是附近幾個輸入的加權總和，而權重在每個位置都一樣。

GPU 的兩層記憶體

GPU 上的資料主要放在兩種地方。它們的差別，決定了很多演算法「理論上快」和「實際上快」之間的落差：

本節帶走
  • 捲積：固定權重滑過序列，可平行。
  • GPU 上「搬資料」常比「算資料」更花時間；把工作留在 SRAM 裡做完，就能大幅加速。

4核心視角：序列建模就是在「壓縮」

這是理解 Mamba 設計理念最重要的一節。論文把所有序列模型放到同一條光譜上比較。

模型讀過的內容可能有一百萬個 token，但它手上能保留的記憶是有限的。所以每個序列模型都在做同一件事：把過去的脈絡壓縮成一個比較小的「狀態」。差別在於壓多少、怎麼壓。

直覺：開會做筆記

一場兩小時的會議，你不可能逐字抄下（那是 Transformer 的做法），但如果每句話都平均地記一點點（固定規則的 RNN），筆記會塞滿「嗯」「那個」。好的筆記是聽到決議就寫、聽到閒聊就跳過，而且要依「當下聽到的內容」來判斷。這個「依內容判斷要不要記」的能力，論文稱為選擇性（selectivity）。

有了這個視角，Mamba 的路線就很清楚了：從一個壓縮效率很高的模型家族（SSM）出發，替它補上選擇能力。下一節先認識 SSM。

5狀態空間模型（SSM）

SSM 來自控制工程與訊號處理，用一個隱藏狀態描述系統怎麼隨時間演變。深度學習版的 SSM（S4 系列）是 Mamba 的直接前身。

5.1 連續時間的版本：一個會漏水的水桶

SSM 最原始的形式是描述「連續時間」的系統，像是物體的位置、電路的電壓怎麼隨時間變化。它只有兩條式子：

h′(t) = A·h(t) + B·x(t)     （狀態怎麼變） y(t) = C·h(t)                （怎麼讀出輸出）

h′(t) 是 h 的變化率（微分）。白話翻譯：狀態變化的速度，一部分由狀態本身決定（A），一部分由外來輸入決定（B）；輸出則是從狀態讀出來的（C）。

5.2 離散化：從連續時間到一步一步

文字是一個一個 token，不是連續的訊號。所以要把連續系統轉成「一步一步」的版本，這叫離散化（discretization）。做法是選一個步長 Δ（每一步代表多長的時間），再用固定公式把 (Δ, A, B) 換成離散版的 (A, B):

A = exp(Δ·A)      B ≈ Δ·B     （Δ 小時的近似） ht = A·ht−1 + B·xt      yt = C·ht

第二行看起來是不是很眼熟？它跟 RNN 幾乎一模一樣，只是少了 tanh 這類非線性，是純粹的線性遞迴。正因為是線性的，才有下一小節的捲積技巧可用。

精確的 B 公式是 (ΔA)−1(exp(ΔA) − I)·ΔB，稱為零階保持法（ZOH）。初學時記住「B 大約是 Δ 乘以 B」就夠了。

Δ 的意義非常重要（Mamba 的選擇機制就是靠它）。用最簡單的例子 A = −1 來看：A = e−Δ，代表每走一步，舊狀態保留多少比例。

ΔA = e−Δ（舊狀態保留）白話
0.010.99幾乎不動：維持記憶、忽略當下輸入
0.50.61新舊混合
30.05幾乎重設：忘掉舊的，專注當下輸入

5.3 同一個模型，兩種算法

舊式 SSM 最迷人的性質是：它可以用兩種完全等價的方式計算。把遞迴式展開看看（假設 h−1 = 0）：

y3 = CB·x3 + CAB·x2 + CA2B·x1 + CA3B·x0

係數 (CB, CAB, CA2B, …) 和輸入無關，可以先算好，記為卷積核 K。於是整條輸出就是 y = x ∗ K，一個捲積！

但請注意這個魔法的前提：A、B、C、Δ 在每個時間點都一樣。這個性質叫線性時不變（Linear Time Invariance,LTI）。只要參數會隨時間或輸入改變，卷積核 K 就不再是固定的，捲積算法就失效了。記住這一點，它是第 6、7 節的伏筆。

5.4 實際的維度：很多個小水桶

實際的輸入不是一個數字，而是每個 token 一個長度 D 的向量（D 個「通道」）。SSM 的做法是：每個通道各自跑一個獨立的 SSM，每個 SSM 的狀態是 N 維的（Mamba 常用 N = 16）。

5.5 LTI 的致命傷：不會「看內容」

舊式 SSM 在音訊、影像這類連續訊號上表現很好，但在文字上一直輸給 Transformer。論文用兩個人工設計的小任務點出原因：

另一個任務叫 Induction Heads（歸納頭），被認為和大型語言模型的「情境學習」能力高度相關。例如序列中曾出現「Harry Potter」，之後再看到「Harry」，模型應該要能預測「Potter」：

…HarryPotter走進教室……Harry→ ?

這需要「根據當下的字，回想起它上次出現時後面接什麼」，同樣是依內容取用記憶，LTI 模型做不到。

本節帶走
  • SSM：ht = A·ht−1 + B·xt，yt = C·ht；一個沒有非線性的線性 RNN。
  • Δ 控制每一步「保留舊記憶 vs. 吸收新輸入」的比例。
  • 參數固定（LTI）時可以用捲積快速訓練、用遞迴快速推論，但代價是不能依內容做選擇。

6選擇機制：讓 SSM 會「看內容」

Mamba 最核心的一步。改動本身非常簡單：把 Δ、B、C 從「固定參數」改成「由當下輸入算出來」。

6.1 改了什麼

舊式 SSM（論文稱為 S4）的 Δ、B、C 訓練完就固定，對每個 token 都一樣。Mamba 的選擇性 SSM（論文稱為 S6）改成每個時間點都用當下的輸入 xt 現算：

Bt = LinearN(xt)     Ct = LinearN(xt) Δt = softplus( 參數 + Linear(xt) ) At = exp(Δt·A)     Bt ≈ Δt·Bt     ht = At·ht−1 + Bt·xt
名詞小抄

Linear：一個全連接層，也就是乘上一個可學習的矩陣，把向量轉成指定長度（下標 N 表示輸出 N 維）。softplus(z) = log(1 + ez)，是平滑版的 ReLU，保證輸出永遠是正數，因為「步長」不能是負的。A 仍然是固定參數，但 At 透過 Δt 也跟著輸入改變了。

6.2 三個選擇性參數各管什麼

  • Δ：專注還是忽略。Δ 大 → 舊狀態被大幅衰減、當下輸入大量寫入（「這很重要，記下來」）；Δ 小 → 狀態幾乎不動、當下輸入幾乎被忽略（「這是雜訊，跳過」）。它扮演的正是 RNN 閘門的角色。
  • B：輸入怎麼寫進狀態。決定當下輸入要寫到 N 個狀態值中的哪些、寫多少。
  • C：怎麼從狀態讀出。決定此刻要從記憶中取出哪些資訊來產生輸出。

論文的消融實驗（ablation，把某個元件拿掉或換掉，看效果差多少）顯示 Δ 最關鍵，但三個一起變成選擇性時效果最好：

6.3 動手試試：固定 Δ vs. 選擇性 Δ

任務：記住最近一個重要數字

橘色 token 是要記住的數字，灰色是雜訊。狀態只有一個數字 h，更新規則是 h ← e−Δ·h + (1 − e−Δ)·x（也就是 A = −1、B = 1 的單一狀態 SSM）。目標：讓最後的 h 等於最後一個橘色數字。

在「依內容選 Δ」模式下，可以點擊任一個 token 切換它的 Δ（小 / 中 / 大），自己設計選擇規則。

玩過之後會發現：固定 Δ 怎麼調都兩難。Δ 小，狀態不會被雜訊沖掉，但也來不及吸收新的重要數字；Δ 大，能記住新數字，但很快又被後面的雜訊覆蓋。只有讓 Δ 依內容而變，才能同時做到「該記就記、該忽略就忽略」。這正是選擇性複製任務在測的能力。

6.4 原來 LSTM 的閘門是它的特例

論文的定理 1 說：如果把選擇性 SSM 設成最簡單的情況（狀態只有 1 維 N = 1、A = −1、B = 1、Δt = softplus(Linear(xt))），它的遞迴式會剛好變成：

gt = σ( Linear(xt) )      ht = (1 − gt)·ht−1 + gt·xt

這就是第 1 節圖 1.2 的閘門公式。也就是說，RNN 的閘門可以看成「選擇性 SSM 離散化之後的結果」，而 Δ 就是閘門的一般化版本。這個連結很重要：它說明選擇機制不是憑空發明，而是把 RNN 界多年來的經驗，用 SSM 的理論框架重新整理。

展開推導（只用到指數與對數）

令 z = Linear(xt)，則 Δ = softplus(z) = log(1 + ez)。

A = exp(Δ·A) = exp(−log(1 + ez)) = 1 / (1 + ez) = σ(−z) = 1 − σ(z)。

A = −1、B = 1 時，精確的 B = (ΔA)−1(exp(ΔA) − 1)·Δ·B = 1 − exp(−Δ) = 1 − A = σ(z)。

令 g = σ(z)，代入 ht = A·ht−1 + B·xt，得到 ht = (1 − g)·ht−1 + g·xt。證畢。

6.5 選擇帶來的三種能力

  • 過濾雜訊：重要資訊之間夾雜無關內容（像口語中的「嗯」「那個」）時，可以直接略過。
  • 越長越好：很多模型給它更長的上下文反而變差，因為無法忽略不相干的內容。選擇性模型可以在需要時「重設」狀態、丟掉多餘的歷史，所以上下文越長，表現理論上只會更好。
  • 邊界重設：訓練時常把多篇不相關的文件接成一條長序列。LTI 模型會讓前一篇的資訊「滲」到下一篇；選擇性模型在文件交界處把 Δ 調到很大，就能清空狀態重新開始。
但是，天下沒有白吃的午餐

參數隨輸入而變，模型就不再是 LTI，第 5.3 節的卷積核 K 不再固定，捲積這條快速訓練的路就斷了。只剩遞迴可以算，而遞迴又要一步一步排隊、還要處理 D×N 這麼大的狀態。下一節就是作者怎麼把它變快。

本節帶走
  • 選擇機制 = 讓 Δ、B、C 由當下輸入算出；模型從「時不變」變成「時變」。
  • Δ 是最關鍵的參數，本質上是一般化的 RNN 閘門。
  • 代價：不能再用捲積加速訓練。

7讓它跑得快：硬體感知的 selective scan

選擇機制讓模型變聰明，也讓它變得難算。作者結合三個經典技巧，讓它在 GPU 上真的跑得快。

先看問題有多大。狀態的形狀是 (B, L, D, N)：批次大小 × 序列長度 × 通道數 × 狀態維度，比輸入 (B, L, D) 大了 N 倍（N 常是 16）。如果照教科書的寫法，把每一步的狀態都存進 HBM 再讀出來，大部分時間會花在搬資料上（回想第 3 節的 memory-bound）。

技巧一：核心融合（kernel fusion）

與其分好幾個步驟、每步都把巨大的中間結果寫回 HBM，不如把整串工作塞進同一個 GPU 程式（kernel），在 SRAM 裡一次做完，只把最後的小結果寫回去。

技巧二：平行掃描（parallel scan）

遞迴不是一定要排隊嗎？關鍵觀察是：每一步 ht = at·ht−1 + bt（這裡 at = At、bt = Btxt）都是一個「線性函數」。兩個線性函數接起來，還是線性函數：

先做 (a₁, b₁) 再做 (a₂, b₂):  a₂(a₁h + b₁) + b₂ = (a₂a₁)·h + (a₂b₁ + b₂) 所以「合併」規則是：(a₁, b₁) ⊕ (a₂, b₂) = (a₁a₂, a₂b₁ + b₂)

這個合併符合結合律（先合併前兩個或先合併後兩個，結果相同），所以可以像淘汰賽一樣兩兩配對、同時合併，不必從頭排隊。

直覺：全班算總分

排隊算法是第一個人算完交給第二個人加，一路傳到最後。平行算法是先兩人一組相加，再組與組相加，幾輪就算完。人多（GPU 的運算單元很多）時，後者快得多。

技巧三：重新計算（recomputation）

訓練時，反向傳播需要用到前向計算的中間狀態。正常做法是把它們存起來，但那正是 N 倍大的東西。Mamba 選擇不存，等反向傳播需要時再從輸入重算一次。聽起來浪費，但因為「重算」比「從 HBM 讀回 N 倍大的資料」還快，整體反而更省。結果是 Mamba 層的記憶體用量，和使用 FlashAttention 的最佳化 Transformer 差不多。

  • 融合：大狀態只活在 SRAM 裡，不寫回 HBM。
  • 平行掃描：線性遞迴的合併符合結合律，可以 log 輪完成。
  • 重算：中間狀態反向傳播時再算，省記憶體也省時間。

8Mamba 架構：把積木組起來

選擇性 SSM 只是一個「序列轉換層」，還要放進完整的神經網路裡。Mamba 的設計原則是簡單：只用一種區塊，重複堆疊。

以往的 SSM 語言模型（如 H3）會把「含 SSM 的區塊」和「MLP 前饋區塊」交錯堆疊，就像 Transformer 交錯 attention 和 MLP 一樣。Mamba 把這兩者合併成一個區塊:

  1. Linear ↑（擴展）：用矩陣乘法把維度從 D 放大到 E·D（論文固定 E = 2）。兩條分支各有一個。更寬的空間讓 SSM 有更多通道可用。
  2. Conv1d（短捲積）：卷積核很短（實作上長度 4），在進 SSM 前先把左右相鄰幾個 token 的資訊混一下，處理局部的小模式。
  3. SiLU：激活函數 SiLU(x) = x·σ(x)，是平滑、非線性的「開關」。整個區塊的非線性主要來自這裡，因為 SSM 本身是線性的。
  4. 選擇性 SSM：第 6 節的主角，負責沿著序列方向傳遞、挑選資訊。這是整個區塊裡唯一讓不同 token 之間交換資訊的地方。
  5. 相乘（閘控）：閘門分支的輸出與 SSM 的輸出逐元素相乘，決定每個維度放行多少。注意這種「架構上的乘法閘門」只在同一個 token 內作用，和沿時間方向挑選資訊的「選擇機制」是兩回事；論文特別強調，光有前者無法解決選擇性複製任務。
  6. Linear ↓（縮回）：把維度縮回 D，好跟殘差相加。

整個模型

本節帶走
  • 一個 Mamba 區塊 = 擴展 → 短捲積 → 選擇性 SSM，再乘上一條閘門分支，最後縮回。
  • 整個網路只堆這一種區塊，加上正規化與殘差連接。

9訓練與推論：同一個模型，兩種跑法

訓練時整段序列都已知，用平行掃描一次算完；生成時字一個一個來，就切回最省的遞迴模式。

訓練：整段文字都已經在手上，用第 7 節的平行 scan 沿著序列一次算完，成本隨長度線性成長。

11限制與後續發展

讀論文要同時看作者沒做到的部分。

作者自己承認的限制

  • 規模：實驗最大只到約 30 億參數，遠小於主流大型語言模型。放大之後是否仍有優勢，論文發表時尚未驗證。
  • 連續與離散的取捨：選擇機制補強了文字、DNA 這類離散資料，但可能削弱舊式 SSM 原本擅長的連續訊號。論文的音訊實驗其實改用了複數版本的參數化，作者也明說這是一種取捨。
  • 生態系：Transformer 累積了大量配套技術（微調、提示、指令調整、RLHF、量化等），這些是否同樣適用於 SSM，仍待研究。

固有的取捨

Mamba 終究是把歷史壓縮進固定大小的狀態。選擇機制讓它壓得聰明，但不可能無損。後續研究普遍觀察到，在需要逐字回想大量前文內容的任務（例如長段落的精確複製、從長文中查找特定細節）上，固定狀態的模型仍不如保留完整歷史的 attention。

後續發展（延伸閱讀方向）

  • Mamba-2（Dao & Gu, 2024）：提出「狀態空間對偶性」，說明某類選擇性 SSM 和一種 attention 在數學上是同一件事的兩面，並藉此改用矩陣乘法來算，訓練更快。
  • 混合架構：例如 AI21 的 Jamba，把少量 attention 層和大量 Mamba 層混著堆，兼顧精確回想與長序列效率。這已成為很常見的設計方向。
  • 其他領域：Vision Mamba 等工作把它用在影像，以及醫療訊號、時間序列等長序列資料。

12總整理與自我檢測

把整份講義串成一段話：序列模型的核心問題是怎麼把過去壓縮成狀態。Transformer 不壓縮，效果好但貴；RNN 和舊式 SSM 壓縮成固定大小，便宜但不會挑。舊式 SSM 靠「參數固定」換來捲積式的快速訓練，卻也因此無法依內容做選擇。Mamba 讓 Δ、B、C 隨輸入改變，補上選擇能力；為了彌補失去的捲積加速，它用核心融合、平行掃描、重新計算在 GPU 上高效實作；最後用單一種區塊堆出整個網路。結果是訓練線性時間、生成每步固定成本，而且在語言上首次追平 Transformer。

自我檢測

為什麼 Transformer 生成長文時會越來越慢？
因為它不壓縮歷史：每個舊 token 的 key、value 都存在 KV cache 裡，每生成一個新字都要讀過整個快取，所以每步成本隨長度成長，記憶體也一直增加。
舊式 SSM 為什麼能同時用遞迴和捲積來算？代價是什麼？
因為參數在每個時間點都相同（LTI），展開後的係數 CAkB 與輸入無關，可以事先算成固定的卷積核。代價是它對每個 token 一視同仁，無法依內容選擇要記住或忽略什麼。
Δ 大和 Δ 小分別代表什麼？
Δ 大：舊狀態大幅衰減、當下輸入大量寫入，相當於「重設並專注在當下」。Δ 小：狀態幾乎不變、當下輸入幾乎被忽略，相當於「略過這個 token」。
加了選擇機制後為什麼不能用捲積？Mamba 用什麼替代？
參數隨輸入改變，卷積核就不再固定，捲積等價關係消失。Mamba 改用遞迴的平行掃描，搭配核心融合（大狀態只放在 SRAM）與重新計算，讓遞迴在 GPU 上也很快。
LSTM 的閘門和 Mamba 的選擇機制有什麼關係？
把選擇性 SSM 設成最簡單的情形（N = 1、A = −1、B = 1）時，離散化後的遞迴剛好就是 ht = (1 − gt)ht−1 + gtxt 的閘門形式。所以閘門是選擇機制的特例，Δ 是閘門的一般化。
Mamba 區塊裡的「乘法閘門分支」和「選擇機制」是同一件事嗎？
不是。乘法閘門在同一個 token 的各個維度上作用，不會在不同時間點之間傳遞資訊；選擇機制則決定資訊如何沿著序列方向被保留或遺忘。論文實驗顯示，只有架構閘門而沒有選擇性 SSM，解不了選擇性複製任務。
